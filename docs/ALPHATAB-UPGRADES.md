# alphaTab upgrade checklist

Guitar Trainer Studio v1.0.2 ships the qualified alphaTab 1.9.0 bundles. Use the procedure and four replay patches below for the current reader. The 1.8.4 inventory and the initial 1.9.0 staging checkpoint document earlier work and rollback. [Installed upgrade and verification](DEV-NOTES.md#installed-alphatab-190--2026-11-20)

## Qualifying 1.9 and later releases

Qualify pause and resume after skipping into a later recorded take of the same written bar. Native Pause can issue an asynchronous seek to an earlier beat. The adapter retains recording time and the audio sync browser regression checks the second take.

The display-only score overlay also supports auditioning a proposed take while ordinary recording timing is selected. Verify the chosen occurrence, hidden native cursor and bounded stop with the audio sync browser regression.

For Loop Speed Trainer, retain the native Finished notification on both continuous synth repeats and non-looping range completion. The host forwards deliberate score and paused fretboard navigation so a partial pass can be excluded. Bootstrap applies the next speed before the host schedules a loop count-in. Run `tests/run-speed-trainer-browser.cjs` against the candidate to check actual pass cadence, the target cap and audio-clock click spacing.

From the GuitarTrainerStudio root in PowerShell, run the following command. Replace the version for the next release. Omit `--install` for a staged report.

```powershell
.\tools\alphatab\qualify-alphatab.cmd 1.9.0 --install
```

The command uses Node, Windows PowerShell, Git, tar, Python, Chrome, Playwright, and the adjacent Lesson Bridge checkout with the saved private controls. Set `GTS_BRIDGE_ROOT` if that checkout is elsewhere. Set `GTS_PYTHON` or `GTS_PLAYWRIGHT_MODULE` for a custom Python or Playwright installation. The package comes from the official npm registry. Private inputs are read locally. Checks run in an isolated Trainer and Chrome profile. The printed report location in Lesson Bridge, `dist/alphatab-qualification/<run>/report.json`, lists each gate, its log and the installation backup path.

The updater checks the npm SHA-512, package files and licenses, then replays the nearest registered patch set in staging. The checks cover stock Basic portability, saved classic/core readback, actual Trainer import/Wait, native layout, tapping, verified and draft sync, and startup. A passing install run registers that exact version, integrity and bundle hashes under `tools/alphatab/ports`. The updater then installs and all installed asset hashes are compared to the tested candidate. A failed qualification keeps the previous vendor folder active. A future upstream change that breaks patch context or musical behavior will identify the failed check for maintenance.

**Rollback after a future upgrade.** If the final installed-file comparison fails after the swap, automatic rollback does not run. The previous copy is retained under `tools/alphatab/.backups`. The run's `install.log` gives its exact path. From the Trainer folder, reinstall the last working qualified version. For example, to return to 1.9.0, run:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\alphatab\update-alphatab.ps1 -Version 1.9.0
```

**Rollback from 1.9.0 to the previous 1.8.4 reader** from the same Trainer folder:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\alphatab\update-alphatab.ps1 -Version 1.8.4
```

Hard-refresh Trainer after installing or rolling back to load its matching main script and worker. The previous vendor folder is also retained in `tools/alphatab/.backups`. The November 5 spacing adapter stays removed.

| 1.9 replay file | Behavior protected |
| --- | --- |
| `alphaTab-marked-scores.patch` | Imports, preserves and exports registered note markings, harmonic pitches, ties, short bars and the final tied measure of an uneven part. |
| `alphaTab-marked-playback.patch` | Produces the intended attacks, bends, releases, repeat behavior and sampled playback for previously supported techniques. |
| `alphaTab-worker-compatibility.patch` | Preserves marked score fields and measure clocks across worker serialization. A local schema ID rejects a mixed stock/patched pair. The coordinated MIDI wire preserves a sampled note's start offset. |

The four diffs apply to both classic and core. Native 1.9 covers the former invalid-string TAB gap patch. Its 1.8.4 patch stays in the rollback plan. The historical inventory below identifies the individual technique contracts carried by the four diffs. The console helper retains its independent writer. Older marked exports still need the compatible reader.

### 1.8.4 inventory and initial staging history

This is the 1.8.4 inventory of Guitar Trainer's alphaTab changes. The app uses the pinned local classic, core, worker and worklet bundles. Do not copy upstream bundles over them or approve a version just because it loads. The [updater](../tools/alphatab/README.md) replays the registered vendor patches on a staged package and only installs the version and bundle hashes qualified in [`patches.json`](../tools/alphatab/patches.json).

### alphaTab 1.9.0 staging checkpoint — 2026-11-20

The official `-Version 1.9.0 -PrepareOnly` run verified the archive and stopped at `alphaTab-tab-gap-bundle.patch` because its context changed. The staged package remains available. The updater stops at the first conflict. Later patch applicability and behavioral equivalence remain open.

Stock 1.9.0 still opens the four marked saved exports, but musical readback differs. 91151's marked pinch sounds MIDI 81 instead of 62. 94723's marked tap sounds 86 instead of 62. 95578's short measure expands from 5520 to 5760 ticks and its explicit zero bend midpoint disappears. 97232's terminal measure shortens from 4440 to 3840 ticks. Retain their reader behavior until a stock-compatible encoding or an upstream implementation proves the exact same notes, positions, ties, expressive shapes and clocks. Qualify the helper independently. Its pinned reader verifies generated files before Send.

The native simile adaptation is a host projection; its bounds and retirement checks are in [the host contract](NATIVE-SIMILE-PRACTICE.md).
