# alphaTab upgrade checklist

This is the current inventory of Guitar Trainer's alphaTab changes. The app uses the pinned local classic, core, worker and worklet bundles. Do not copy upstream bundles over them or approve a version just because it loads. The [updater](../tools/alphatab/README.md) replays the registered vendor patches on a staged package and only installs the version and bundle hashes qualified in [`patches.json`](../tools/alphatab/patches.json).

1. Keep a known-good checkout. Run `update-alphatab.ps1 -Version <version> -PrepareOnly`. This verifies the official archive and tries the patches in order without touching the installed assets. A patch conflict retains the verified archive for porting. Start over from the archive before replaying revised patches; the candidate may already have earlier patches applied.
2. Use the search anchors above on the **new** bundles. For example: `rg -n 'collectSpaces|notesPerString|isRightHandTapped|_getNoteDuration|GtsSlidePlayback|GtsRepeatTieRelease|loadedMidiInfo|AlphaSynthAudioWorkletOutput' <candidate-folder>`. Port any unmatched patch to the new code and retry against a fresh candidate. If upstream already provides a fix, retire the local patch only after the existing regression proves equivalent behavior. Requalify version-gated host adapters in an isolated checkout before updating their version checks.
3. In that isolated checkout, use the staged bundles to run `node --test tests/*.test.js` and the relevant browser checks in the inventory, including `run-lesson-import-browser.cjs` and `run-loop-media-repeats-browser.cjs`. Hard-refresh and check installed playback, rapid Pause, seeking, repeat loops, print and recording alignment. Keep manual MIDI/hardware acceptance separate from automation.
4. Once the candidate passes, update `patches.json` with the qualified version and exact upstream and patched SHA-256 values, then run the updater against the same version. It regenerates `vendor-manifest.json` from the verified inputs and patched files. Check licenses/source notices and run `test-updater.ps1`. Record the upgrade and evidence in [DEV-NOTES.md](DEV-NOTES.md). Keep the old bundle until acceptance.

When adding or changing an alphaTab adaptation, update this inventory and its regression in the same change. For vendor edits, also update or add the reapplicable patch, its entry and hashes in `patches.json`, the installed manifest, and the MPL source references. List source-only patches under `referencePatches`; the updater rejects missing or unregistered patch files. Cover the classic and core/worker paths where the feature uses them. For host adapters, record the upstream search anchors, version or signature gate, and criteria for retiring the workaround. A proposed feature belongs here once implemented, not before.
