# Lesson Bridge: local Chrome lesson import

Lesson Bridge for Guitar Trainer Studio is an optional, locally installed desktop Chrome extension. It scans the page you choose for score, recording and timing candidates, then can send your selection into an already open Guitar Trainer tab. The app asks you to review before replacing its score. Nothing saves or starts playing automatically. Guitar Trainer still works without the extension.

## Install for testing

1. Use your normal desktop Chrome profile, where you sign into TrueFire.
2. Open `chrome://extensions` and enable **Developer mode**.
3. Click **Load unpacked** and select the `extensions/lesson-bridge` folder inside this repository. Select that folder, not the repository root.
4. Pin **Lesson Bridge for Guitar Trainer Studio** from Chrome's extensions menu.
5. Open a lesson you can access. Let its player load and reveal its download links. Click the extension, then **Scan this page**.
6. Review candidates. For a timing JSON candidate, **Inspect timing** asks for access to that HTTPS host and tries to display a validated Soundslice timing preview.
7. Keep Guitar Trainer open in the same Chrome profile. In the extension, select the score and optional recording/timing. First use defaults to `https://ztbishop.github.io/guitar-trainer-studio/index.html`; an existing valid saved address takes precedence. To use another copy, enter its **exact address** from the address bar (including the actual Live Server/launcher port and any project subfolder). Use HTTPS for hosted copies or HTTP localhost/127.0.0.1 locally. Valid edits save immediately in the extension's `chrome.storage.local`, without needing a successful Send; lesson resources are not saved. Invalid/unreadable saved values fall back to the hosted default.
   Include **`/index.html` at the end** of a custom app URL, after any project subfolder—for example, `http://127.0.0.1:8081/index.html`.
8. Click **Send selected lesson**, grant the requested site access if wanted, and keep the popup open until sent. One matching app tab must already be open; duplicate matching tabs produce a recovery message. No download file is left in Downloads.
9. Guitar Trainer opens one review. Choose **Import lesson** to replace the current score/unsaved sync work, or **Cancel** to leave it alone. A successful score-only import or recording import with validated timing automatically finishes editing and closes the dialog, leaving a brief nonblocking “Lesson ready” message. Press Play when ready. Without timing, the dialog still closes but Media Sync stays open for manual alignment; choose **Finish editing / Return to practice** after aligning. Errors remain in the dialog. Save to Library and Save profile remain separate optional actions.

After code updates, click the extension's reload button at `chrome://extensions`, hard-refresh Guitar Trainer, refresh the lesson and scan again. The extension must be reloaded for new permissions/modules to take effect. Uninstall it there when no longer wanted. No store account, Node helper or server is required for the extension; your app still uses Live Server or its normal launcher. A future store listing can be private for testers, then unlisted/public when wanted. Nothing has been submitted to Google.

The extension uses the existing Guitar Trainer app icon in Chrome. **Send selected lesson** is available beside **Scan this page** after a successful scan, as well as below the selectors. Both send the same current choices and disable together during scanning/sending. A failed scan disables the shortcut until a successful rescan. The existing Send status remains below the selectors.

Scan results disappear when the popup closes. Query parameters and encoded redirect destinations are hidden in the review. The extension stores only the app address in `chrome.storage.local`, not lesson URLs, credentials, score bytes or timing. No telemetry, cookies API or background listener is used. Explicit download requests use the browser's available session; signed links, cookie policies and publisher access still apply. Optional host grants remain in Chrome until revoked through extension/site access settings or uninstalling. Score downloads are bounded to 12 MB; timing JSON to 1 MB. Remote HTTPS retrieval is supported; generic HTTP sites other than loopback are not granted fetch access. After review, the app holds the imported score/recording/alignment like an ordinary loaded session; only explicit library/profile saving persists them, and saved online profiles can contain expiring media URLs.

## What the scan can find

- Guitar Pro (`gp`, `gp3`, `gp4`, `gp5`, `gpx`) and MusicXML (`xml`, `musicxml`, `mxl`) links. File extensions/labels identify candidates, not validated file bytes. A label-only candidate may still be an ordinary web page.
- Media links and HTML player sources, including streaming playlist names and encoded TrueFire MP4 routes. MP4 is preferred when available. Soundslice soundfont/metronome assets and malformed empty-ID timing links are filtered. Download-MP3 jamtrack links are excluded from the recording picker for this lesson-video workflow; review remaining candidates rather than assuming automatic pairing.
- Timing JSON links and TrueFire's player manifest when exposed in the inspected page/frame resource names or player URL IDs.
- Same-origin frame contents, quoted URL declarations in bounded inline scripts and already loaded resource names. This is a snapshot, not interception of every network request. Cross-origin frames, JavaScript-only player state, `blob:` media and undisclosed links can be missed. Start the player and rescan when needed.

On TrueFire only, a same-origin `soundslice_manifest` endpoint is read using the page's existing session. Standard `/vNNN` lessons and Methods/Channels are supported. Player iframes may expose cid/sid or legacy courseid/lessonid. Standard lesson IDs must agree with the player; Methods `/lNNN` navigation IDs are never substituted for player lesson IDs. Observed manifests must match the player identity, or the endpoint is constructed from exposed numeric IDs. Stale lesson timing/manifests are filtered. No IDs are guessed, unrelated lessons queried or scripts evaluated.

The signed-in Methods example, Practice Session 17 at `/l34943`, embeds course 1069/player lesson 34884. Its manifest exposes recording and timing; its visible score download is a PDF chart. Automatic selection can therefore send recording/timing against an already loaded matching score, but cannot supply a Guitar Pro file that the lesson does not expose. Revised installed-extension acceptance remains pending.

**Inspect timing** supports Soundslice arrays containing playback bar number, recording seconds, optional within-bar position (0–480), and optional hide-playhead flag. It checks basic order/ranges and shows up to 12 points. Standalone preview does not confirm score compatibility. Preview timing requests reject redirects; selected Send downloads use the extension's granted host access and normal redirects. There is no separate streaming player/HLS adapter; use MP4 when offered. If a recording fails, the opened score remains usable; retry another recording choice or use manual Media Sync.

**Imported timing** is independently revalidated in the app. Playback bar numbers map into alphaTab's expanded measure occurrence list, positions divide by 480 and seconds multiply by 1000. A final bar equal to the performance measure count maps to the last measure's end. A complete terminal anchor matching the score's performance length is required; partial/mismatched data, non-increasing positions/times, out-of-duration points or hide-playhead flags are rejected rather than silently approximated. Matching length is necessary but does not prove matching musical content; review audible alignment across the lesson. Score-only imports and recording-without-timing imports are supported. There is no conversion from internal Soundslice notation.

## Current partial-import and embedded-player limits

### Copy timing separately

Every candidate card also has **Copy link** for its full original URL, including any access parameters hidden in the display. This is available for score, recording, timing and manifest candidates. Clipboard failure exposes a selected full-link field for manual Ctrl+C/Command+C. It copies a resource URL, not the contents of that resource; use Copy sync points below for actual timing data. Links may expire, and copied access parameters should be handled like the original links. Nothing is persisted or uploaded by copying.

1. Scan the lesson, find a Timing candidate and click **Inspect timing**. This works without a detected score or recording when the scan exposes a readable timing resource.
2. Click **Copy sync points**. It copies the complete numeric JSON array, not only the first 12 preview points. If clipboard writing is blocked, the full JSON field is selected; use Ctrl+C or Command+C manually. No clipboard-reading permission or additional extension permission is used.
3. In Guitar Trainer, load the matching score first, then its video/audio (a later new score clears the previous recording). Open the Media Sync editor, expand **Paste sync points**, paste the JSON and click **Apply pasted sync points**.
4. Review alignment, then Finish editing to practice. **Undo** restores the previous alignment; **Save profile** keeps the change. Applying timing does not replace the loaded score or recording and does not save or start playback automatically.

The paste action requires a loaded score and recording and independently validates the entire array against native expanded measure order and recording duration before editing. Mismatched/invalid JSON, unsupported hidden-playhead data or incomplete endpoints leave the prior alignment intact. Normal alignment editing resets practice through existing host callbacks; no grading rules change. Pasted text is temporary and clears with recording disposal/score replacement. Copying does not overcome an inaccessible embedded frame: the extension must first find and read a timing resource.

Send accepts a new score, recording, timing or any combination. **Use score already loaded** retains the ready score in the app. No new recording retains it when keeping the score; **Keep current recording even with a new score** explicitly reattaches an external/local/YouTube recording across score replacement. Embedded backing audio cannot be carried across scores. A new score otherwise clears its recording. Changing score/recording clears prior alignment; supply matching timing or align manually. Timing alone preserves resource identities and uses ordinary edit/Undo/profile identity. A no-op Send is rejected. The app review describes the selected effects. A PDF, tab image or internal Soundslice notation JSON cannot become a practice score.

**Manual selection** exposes all discovered candidates in each role picker, including plausible unclassified downloads/PDF/JSON. You can paste asset URLs, a score filename or complete Soundslice timing JSON. **Test score** downloads bounded bytes and checks basic format headers; final parsing happens in Guitar Trainer. **Test timing** checks structure, not musical compatibility. **Test recording** opens native media or YouTube without autoplay; press Play to check playback. Previews close on recording change, rescan and Send. Streaming depends on browser support. Dropbox preview pages are not automatically converted to raw files; manual assignment does not convert unsupported formats.

The cross-origin frame notice means the snapshot could not read that embedded document; it does not prove video/timing are unavailable. Exposed parent-page resources can still be discovered. Scanning the embedded host directly with additional Chrome host permission is a possible follow-up, not implemented here. A plain video player may have no musical score synchronization data at all, even when video access works. Investigate a representative Teachable/player URL before requiring manual DevTools extraction or promising universal sync detection.

## When there is no Guitar Pro download

MusicXML is also usable directly in Guitar Trainer. A Soundslice player alone does not establish that a downloadable original score exists. Soundslice exports GPX/MusicXML for self-created slices on a paid account; paying for Soundslice does not automatically confer edit/export access to a publisher's embedded slice. Its authenticated Data API has separate permissions. An agent moving a lesson into a personal Soundslice account might simply download a provided score and upload it; the reported forum workflow has not been inspected.

Conversion from internal Soundslice notation would be a separate feasibility/fidelity project. This extension does not reconstruct notation, perform PDF recognition, copy lessons into Soundslice or claim support for unavailable downloads. Missing timing can use the existing manual alignment editor; a missing supported score cannot become a practice score merely from video/timing data.

## Developer continuation

The extension is optional and uses its own prototype version 0.2.0; the app remains Beta v0.0.4. App runtime imports no files from the extension folder, so the existing local launcher allowlist only adds the app's new review stylesheet.

| File | Responsibility |
| --- | --- |
| `manifest.json` | Manifest V3 popup, temporary active-tab/scripting access, storage for app address only and optional HTTPS/HTTP-loopback grants. No background process or automatic injections. |
| `scanner.js` | Self-contained serialized `scanPage` function: read bounded top-page/same-origin frame observations, optionally read the TrueFire same-origin manifest, return candidate observations and notices. No alphaTab/MIDI/app calls. |
| `discovery.js` | Pure URL validation, redirect destination classification, deduplication/caps, redacted review URLs and Soundslice timing array validation. |
| `popup.js` | Scan/review, resource selectors, app address preference, gesture-triggered permission requests, bounded download orchestration and exact target-tab matching/focus. Successful timing inspection also exposes complete JSON with user-triggered clipboard copy and selectable-text fallback, independently of score discovery. |
| `transfer.js` | App-address validation, bounded session-aware score/timing fetch, base64 serialization and isolated-world one-shot delivery/acknowledgement to a selected app tab. |
| `popup.html` / `popup.css` | Local popup content and presentation. No remote scripts or dependencies. |
| `js/lesson-import-data.js` | Independent app-side versioned payload/byte validation and Soundslice-to-native-flat-point conversion against the existing normalized timeline. No alphaTab/player calls. |
| `js/lesson-import.js` / `lesson-import.css` | Same-window/same-origin offer listener, text-only replacement review, explicit acceptance, injected score/media orchestration, readiness/cancellation/status. Success closes review and shows a six-second nonblocking notice; errors keep the dialog. No URL-driven score fetch, grading or direct native API calls. |
| `js/media-controls.js` | `importLesson` uses the existing recording loader/editor/selection, marks imported alignment unsaved and rejects obsolete score/source work. Valid imported timing invokes the existing `finishEditing` path automatically; absent timing keeps manual alignment open and returns `readyToPractice:false`. The existing `finishEditing` operation is exposed to the receiver for score-only completion. `timelineReady` shares its pending hash/profile initialization promise with import callers. The manual paste handler parses bounded JSON, uses soundslicePoints against the current timeline/duration, then calls the existing edit/Undo/dirty/native-host path without reloading resources. |
| `js/app-bootstrap.js` | Initializes the receiver and forwards score-loading invalidation. Existing host remains the only native runtime owner. |

Current transfer schema: `{format:'gts-lesson',version:2,title,lessonUrl,score:{fileName,base64}|null,recording:{url,label}|null,syncPoints:SoundsliceArray|null,keepRecording:boolean}`. Version 1 remains accepted with its mandatory score. Version 2 rejects empty updates and requires a ready app score for recording/timing-only updates. Chrome executeScript arguments use JSON-safe base64. `deliverLesson` posts `gts-lesson-offer` with a random request ID to the exact app tab; the same-window/same-origin receiver acknowledges review queuing. This is not cryptographic extension authentication: no changes or recording requests occur before accepted review. Publisher access restrictions still apply.

After acceptance, loading uses `loadScoreFile(new File(...))`; the receiver waits for the matching native score bytes/timeline/player. A subsequent score load invalidates pending work. Media controls check score and generation before/after asynchronous operations; loading/import failure reports partial state rather than claiming rollback or success. Imported points clear any matched profile ID and stay unsaved; ordinary Save profile/library identity rules remain. Closing the sync editor uses the existing native practice restoration. No changes to MIDI matching, Wait progression, feedback rules, or practice timeline generation; alphaTab integration remains exclusively in `js/alphatab-host.js`.

Future work remains broader provider/arrangement acceptance, permissioned embedded-frame scanning, expiring-link refresh and separately scoped store publication or notation conversion. Generic discovery is not universal import. Current module responsibilities and partial-update lifecycle superseding older descriptions above are detailed in ARCHITECTURE.md under Methods discovery and selective lesson updates.
